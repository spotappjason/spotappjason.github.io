0.8.2 — 1 October 2026

  • Mac only, like 0.8.0 (GitHub's build service is still unavailable).

Fixed

  • The search spot splits again when you type (the "mitosis"). With macOS Reduce Motion turned on, the first letter made the spot jump straight to the search pill: no split into two dots, no sticky neck, and the dictation shape stood still. Spot's notch animation now plays whatever the Reduce Motion setting says, as intended. Other apps and the rest of macOS still follow your setting. (Announced for 0.8.1, but that build was made before the fix was merged; this is the first release that contains it.)

  • later release once the Windows build and CI run again.

Added

  • Search by meaning is on by default (PR #19). Account → Search by meaning has an on/off switch. Once you are signed in, Spot indexes your saves by itself, and every new save — including unfiled Inbox saves — gets its meaning vector when it is captured. Only text is sent (titles, sentences, tags, saved passages), through Spot's proxy to Voyage AI; pictures are never sent. Turn it off in Account to send nothing.
  • Windows x64 NSIS and portable build targets, platform-specific paths and labels, and screenshot watching. A top-center hover panel serves Windows and Macs without a hardware notch. These are implemented in source but not in this Mac-only release; native Windows installation and update acceptance remain to be verified.
  • An evaluation harness with graded relevance metrics, candidate pooling, class breakdowns and lexical-field ablations. The reference query file is still unfilled, so no retrieval-quality improvement has been established by a real graded evaluation.
  • Selected-text capture (Mac, PR #17). Highlight text in any app, move the pointer to the notch and click the white circle: the passage is saved to the Inbox with where it came from (the page link in Chrome and Safari, the document or app otherwise), and the capsule opens with "Why keep this?". The clipboard is never touched and password fields are refused. It is off until you turn it on in Account and allow Spot in System Settings → Privacy & Security → Accessibility. Saved passages and unfiled Inbox screenshots are found by notch and main-window search. Verified by hand on the development build in Chrome, Safari and TextEdit; the packaged app's own Accessibility grant and Intel Macs are not yet hands-on tested. Because this build is unsigned, macOS may ask you to grant Accessibility again after an update.
  • The notch's cursor-following pupil, the capture capsule and offline English dictation arrive in the same PR.
  • The circle appears only when text is highlighted (PR #18, branch feat/notch-revision). Bringing the pointer to the notch with nothing selected shows nothing — no circle, no popup. A problem Spot found on its own (no Accessibility permission, an app that hides its text) is not shown at the notch; the Accessibility status is in Account. A click that fails says so in one small line.
  • Fn: hold to dictate, double-tap to type (PR #18, branch feat/notch-revision, Mac). Hold Fn and speak into the notch search (or the open capsule's "Why keep this?", or the main window's search when it is in front); release to stop. Double-tap Fn to open the search box and type — this never uses the microphone. Fn together with another key does nothing. Needs Accessibility (the same permission as selected-text capture) and a keyboard whose Fn key reaches macOS. Control+Shift+Space and ⌘⇧K still work.
  • Capsule: Up/Down and Delete (PR #18, branch feat/notch-revision). Up and Down replace + and − and step through what is waiting in the Inbox — dragged-in images, screenshots, passages and links not saved yet — newest first. Delete (red when the pointer is on it) moves a saved reference to the Trash or discards a link that was never saved.

Changed

  • Search uses evidence-weighted rank fusion by default, with same-facet sibling credit disabled in the live taxonomy. Typed facet constraints and negative terms are parsed; lexical and dense constraint-relaxation behavior still has the gaps documented in SCORING.
  • Canonical embedding text omits date, orientation, dimensions and language; those fields remain metadata. This change does not implement date filtering or image embeddings.
  • The release command requires Mac and Windows CI for the tested source and validates both platform feeds, required architectures, hashes, sizes and uploaded assets before publication. Build manifests protect resumed uploads against replaced artifacts. The one exception is typed on purpose: SPOT_MAC_ONLY=1 npm run release publishes the Mac half alone without the GitHub CI gate (this Mac's npm test, the smoke test and every Mac feed, hash and upload check still run). It is ignored when written in release.env, and a resumed release keeps the mode it was built with.

Fixed

  • Search finds your Inbox saves (PR #19). Unfiled saves only matched when every typed word appeared exactly as written — "bedroom" found nothing though "Minimal Bedroom With Paper Lamp" was there — and search by meaning could never turn on with only Inbox saves. Filed and unfiled saves are now ranked by one engine, including the words read off a picture and its file name. A failed meaning pass keeps the word results and says "meaning unavailable: …" instead of silently doing nothing.
  • The spot keeps one size (PR #19). The dots shrank from 10.64 to 8 px as soon as you typed; one geometry now drives every state.
  • A highlight saves on click (PR #19). The "this app hides its selected text" message and the Paste box are gone: where macOS can't read a highlight, clicking the spot copies it and puts your clipboard back. Clicks are no longer refused as out of date, and a waiting highlight shows the spot's dot, not a quotation mark.
  • Selected text from any app (PR #18). Apps that don't share their text with macOS (drawing apps, some editors) now work too: Spot uses the app's own Copy for a moment and puts your clipboard back exactly as it was. The copied words may appear in a clipboard manager's history. Apps that do share their text are read as before, clipboard untouched.
  • Clicking the notch's circle works again (PR #18). A zoom saved for the notch window (for example after ⌘+ while the notch had focus) made everything in it larger and moved the circle away from where clicks land. The notch now always stays at 100%.
  • The Accessibility permission now sticks (PR #18, branch feat/notch-revision). Without a Developer ID the Mac app was left with a broken signature, so macOS could not match the permission you gave it and kept asking. Builds are now properly signed ad hoc as com.jasonhong.spot. After updating you may still need to allow Spot again, once per update, until the app is signed with a Developer ID.

Fixed — audit branch

  • Dense evaluation calls the embedding client correctly with query input type. Candidate pooling and reporting honor the same configuration. Entirely ungraded queries do not reduce Success/MRR. Evaluation and release regression checks run under npm test.
  • Mac pkg creation preserves the updater configuration by reusing the app built for dmg/zip. Windows CI embeds the actual release repository, selects the exact release-tag run, and verifies reused artifacts against recorded hashes.
  • Portable Windows copies offer a matching portable download for manual replacement rather than starting the NSIS installer. Unsigned Mac copies continue to announce updates for manual install.

Release prerequisites

  • A two-platform release needs the GitHub workflows to run and pass on Mac and Windows; they could not start on 2026-09-27 (account billing), which is why this release is Mac only. Native Windows tests have not been run.
  • Use a clean checkout at GitHub's main; the original local main held an unpublished "Spot 0.7.11" commit and tag, which must be set aside first (git branch abandoned-0.7.11-bump def647f, git tag -d v0.7.11, git reset --hard origin/main, rm -rf dist).

0.7.10 — 16 September 2026

Added

  • Describe reads more off the picture. Your AI now returns the words it can read on the picture and their language, names the dominant colours as color: tags, turns what any text is about into subject: / theme: tags (a poster about coffee → subject:coffee), and treats your own sentence as what the picture must be found by, mapped onto your vocabulary first. Kept in the sidecar as words: and language:, searched as prose, and part of the meaning text. (Merged after 0.7.9 shipped — it is in 0.7.10, PR #5, together with the two lines below.)
  • Embeddings on voyage-multimodal-3.5 at 1,024 dimensions — Voyage's multimodal endpoint with output_dimension, in the Worker and the developer path; the width was verified against Voyage's docs (256 · 512 · 1,024 · 2,048 offered; 1,024 chosen).
  • The notch search field says "Spot it" again.

Changed

  • A moodboard with a few pictures gathers near the middle. The clusters on a board sit on a ring, and that ring had a floor of 700 px — so three results were flung to the far left, middle and right of the canvas with nothing between them. Now the ring is exactly as small as it can be: it grows until no tile of one cluster comes within 77 px of another, so a handful of pictures sit close together in the centre and a board of thirty still spreads out to fit. Boards already saved keep their positions; new ones get the tight layout. The layout moved out of main.js into board.js (pure, no electron) with its own tests (test/board-test.js, 23 checks: the three-picture case from the report, six in three pairs, thirty in six clusters, the saved format unchanged). (board.js, main.js, 2026-09-15)

Fixed

  • The notch closes again after a search. Once results were on the arc the popup told the app "typing" and never took it back, so moving the mouse away left it hanging open. Now "typing" means keys are going in: the flag drops 1.5 s after the last keystroke, and a finished search never holds the notch. Move away and it closes; come back and the query and its arc are exactly as you left them (× or esc clears them, as before). The capture prompt is unchanged: a half-written note still holds it open until saved or put away. (renderer/notch.js, 2026-09-15)
  • AI widening no longer shrinks the results. "lights" found 24 pictures, then the tags your AI added turned that into 4. The longer query was scored across all of its terms, so a picture that matched only the typed word satisfied a smaller share of it and fell under the Related net. Widening is now a union (engine.widen): every picture keeps the better of its two scores, the typed word's results stay, and a picture joins through the added tags only if it *carries* one of them — an added subject:lamp also hands same-facet half credit to every note with any subject tag, which was lifting a mule and a red car into "lamps". Notch arc and the main window both. test/engine-test.js (15 checks: stems, the lamp ↔ light synonym, prose credit, the sibling net, widen). Also, in this vault's TAXONOMY.md, light joined the lamp synonyms so "lights" reaches the four lamps and the streetlamp. (engine.js, main.js, renderer/app.js, 2026-09-15)
  • "lamps" returns lamps. Three leaks, all in what counts as a match in a note's text. (1) A *synonym* word found in the prose earned 0.40, exactly the floor of the Related net, so every note whose text merely contained "light", "lighting" or "pendant" was a result for "lamps" — 21 of 28. It now earns both discounts, prose × synonym = 0.34: still ranked, visible at Everything, not a result at Related. (2) wikilinks and !embeds counted as prose, so a "see …streetlamp… for the set" cross-reference made a picture of birds over a boat a lamp; links are stripped before matching. (3) The note's title (its file name, the person's own words) was not searched at all; it is now part of the prose, which also covers what stripping the links loses. test/engine-test.js grows to 25 checks. (engine.js, 2026-09-15)

0.7.9 — 14 September 2026

Added

  • Search by meaning, the whole system, switched off (VECTORS, D14, 2026-09-14): vault.js (the indexer, shared), vectors.js (canonical text, grammar vectors, the append-only store in App data, compaction, limiter, query cache, embedding client), meaning.js (the app's glue), engine.blend (meaning can only lift, never demote), proxy/worker.mjs (the Cloudflare Worker that holds Spot's key and meters per account — written, tested, not deployed), npm run vectors (a dry run: 244 notes → 8 calls, ~25k tokens, ~$0.002, 0.95 MB), a "Search by meaning" card under Account, 62 tests. Nothing runs until proxy-config.json has the proxy's URL; no picture is sent. Draft PR #2 on spot-app (branch worktree-vectors).
  • Spot later → Delete. In the capture prompt, a trash button beside the ‹ › stepper and ⌘⌫ move the screenshot and its note to the macOS Trash — recoverable, never deleted outright. One press (the user's call: the Trash is the safety net); the strip moves on to the next one. The Inbox tab gets the same Delete on every row. (inbox.js, 2026-09-14)
  • A screenshot can carry a link and a description. The capture prompt's link row is always there, always last, for screenshots and link notes alike; a link dropped onto the notch lands in it by itself, and when no picture can be fetched from a dropped link the prompt opens as a link note with the address filled in. The Inbox tab shows the link and lets you edit it before filing; it is kept in the sidecar as url:.
  • Save with nothing typed. With an AI connected, pressing Save on a screenshot with the note empty hands the picture to your own AI (D12): it writes the sentence, a title and tags, which are kept with the capture (title:, ai-tags: in the inbox note — never tags:, so an unfiled capture is not a block) and carried into File it. Without an AI, the prompt says to type one line.
  • Vectors know the date and the format. The indexer reads each picture's size from its header (PNG, JPEG, GIF, WebP; no decoding) and every block carries width, height and an orientation (vertical · horizontal · square) plus its date (date:, else added:). Both go into the text the meaning model reads and are stored beside the vector as facts for filtering (VECTORS).
  • Onboarding asks for file access. A new second step, "Let Spot manage your files": Check access reads the vault and writes a probe into _inbox, which is what makes macOS show its own permission question for Desktop, Documents or Downloads; blocked → the reason, a hint, and a button to System Settings → Privacy & Security. The app's Info.plist now carries usage descriptions so that prompt states why Spot wants the folder.
  • The website's changelog page is generated from this file. npm run site-changelog renders every shipped version to changelog.html; npm run release does it as step 7 and pushes the site, so the page can never drift from this log.
  • Pro describes on Spot's key, switched off (D15). A person with no key of their own is served through Spot's proxy: the Worker's /anthropic/v1/messages checks the account is Pro, counts 200 pictures a month, forwards to Anthropic with Spot's key; text-only requests (widening) pass without counting. Off until proxy-config.json says describe: true and the Worker is deployed; a person's own key is always used first. The Account card says which key is in use.
  • A Later button (×, and esc) on the capture prompt: puts a dropped screenshot away — it stays in the inbox — and closes the popup instead of waiting for the pointer to leave.

Changed

  • The notch popup in Apple's language. Restyled on the principles in the Apple Design System catalog (clarity, deference, depth, hierarchy, harmony, consistency): the system font, Apple's semantic dark colours (label / secondary / fills / separator), concentric 22 px corners, a search field with its glyph, a segmented control for Screenshot / Link, one blue capsule action, red for delete, 8-pt spacing, a lifted shadow and hairline edge; Reduce Motion honoured. The band stays pure black so it reads as the notch. No Apple files shipped; same geometry, same behaviour.
  • The design canvases (design/, 4.8 MB, never loaded by the app) moved out of the code repo to ~/design/spot/canvas/.

Site

  • Pricing page rebuilt on the decided plans: Free 40 pictures on your own key · Pro $10 a month (unlimited pictures, moodboards, 200 describes on Spot's key, iPhone coming) · Cloud +$10 a month (100 GB, search from anywhere). Monthly only; Studio, Once and the yearly toggle are gone.
  • changelog.html — every version, newest first, the same plain-page shape as the privacy page.
  • Privacy policy rewritten as twelve numbered articles, effective 2026-09-14: what stays on the Mac, what is stored online, who else receives data, search by meaning (not yet available), this website and its hosting, cookies (the site sets none, so there is no banner), legal bases and retention, your rights and how to delete everything, security, children, changes and contact.
  • Landing page: the version pill opens the changelog; the Privacy row says the site sets no cookies; footer gains Changelog and Cookies.

Fixed

0.6.0 — 7 September 2026

Added

  • Reasoning on every result. Each match now records *what* it matched (the tag, the synonym, or the word in the note) and can explain itself in one sentence per term. Shown in the notch's large view ("Why: …") and in the main window's detail panel ("Why it matched …"). A false search is now a specific, fixable line — a synonym to remove, a word in a note.

  • Cluster reasons on boards. Each cluster label says why it exists ("9 of the pictures carry theme:vintage"); the board bar explains the rule (a cluster = a tag ≥ 2 results share, the query's own tags excluded, top five, the rest → "more").

Changed

  • Boards spread out. Pictures in a cluster now only brush each other (~25% overlap) — golden-angle spiral spaced at 0.78 × tile — and the ring radius is computed from the largest cluster so clusters don't collide.
  • Drop outline traces the notch. The white outline now runs down the notch's sides and along its bottom, not just around the panel.
  • Image fetches send a Referer for CDNs that insist on one.

0.2.2 — 7 September 2026

Fixed

  • "shoes" didn't find all the shoes. The engine matched letters, not meaning: of 15 shoe-related blocks, the word "shoes" appeared in only 2. Three fixes:
  • Stemming — singular/plural are one word now (*shoes* = *shoe*, *boots* = *boot*).
  • Synonyms map in TAXONOMY.md ("synonyms"), bidirectional, content not code: *shoes* → boots, derby-boots, mule, sneakers, converse, sandals, footwear…; *boots* → shoes. Scored at phi.synonym 0.85 and shown with ≈ on the why-chips. Seeded for shoes, lamp, denim, jacket, tee, video, photo, label, packaging — grow it whenever a search misses.
  • Prose weight 0.3 → 0.4 so a real mention in the note clears the arc's Related line for one-word searches. ("heels" dropped from the map — it was matching a boat's heel.) Result: "shoes" 2 → all 15 shoe-related blocks on the arc (2 exact, 3 synonym, 10 prose).
  • SCHEMA.md was being indexed as a block (its example frontmatter has subject:shoe) and appeared in results. Root docs (SCHEMA, README, INDEX, LOG, TAGS, OVERVIEW) now excluded.
